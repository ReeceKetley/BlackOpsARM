# Native engine event fences, stage37

Real VkFence tokens back native event pool owners and alias slot addresses; COM pointers remain null. R_HW_InsertFence/R_HW_IsFencePending adapters use those tokens. In a recording scope, insertion records a pending marker and retains it in its frame arena. Only the successful frame-submission callback submits a zero-batch VkQueueSubmit with the token fence; completion covers previous queue work and is polled via vkGetFenceStatus. Semantics conservatively complete the whole submitted frame rather than mid-frame work. Outside recording, queue-owner insertion submits directly. Arena retirement waits each actual event fence, not merely its earlier parent frame fence. Clear waits submitted aliases; device context changes reject live owners/borrowers.

Native R_FinishGpuFence uses actual queue idle on the queue owner and rejects an active unsubmitted frame. Canonical R_CreateForInitOrReset has real native event allocation (flush+8pool entries) plus native sun/corona/flare/pixel-count owner allocation after preceding targets/buffers/services; this full routine has NOT been exercised by the diagnostic. Shutdown/reset clears event owners and releases native pixel-count owners. Existing legacy tokens in r_init/cl_compositing/r_setstate_d3d remain identical after guards/helper additions are excluded.
