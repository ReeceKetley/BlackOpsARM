2026-10-14. Native replacement remains incomplete. This stage begins canonical engine resource adaptation rather than another independent presentation implementation.

The original load-definition ownership assertions, DWORD program-size convention, disabled-renderer handling and vertex creation-skip policy remain. Native creation copies bytecode and produces a real SPIR-V/reflection record. Failure is explicit via canonical Com_Error; it does not publish an empty successful shader. D3D9 COM slots are not populated with forged handles. Default selection remains D3D9 until the remaining backend is connected.

Native registry records are keyed by typed canonical MaterialVertexShader/MaterialPixelShader owners, with owned names/bytecode/translation and unique serials. Acquire returns immutable shared ownership, publication/removal is mutex-protected, and owner removal is idempotent for shared pass aliases. Borrowed records can survive database-side release for a frame already holding them. Backend deselection rejects registered owners. Creation rejects replacing a live D3D9 shader. No FastFile/disk/native shader-structure layout changed. GPU modules still derive from semantically linked records at pipeline creation; the load record is CPU shader ownership, not a live Vulkan pipeline.

`Material_ReleasePassResources` removes native owner entries before retaining the original COM and declaration release behaviour. Reset/shutdown-wide ownership and pipeline retirement still need the final engine lifecycle integration. The native registry is now part of the database archive with the shader translator, so canonical loader dependencies resolve for the APK and compatible full archive consumers. No compiler/assertion/sanitizer policy weakened.
