## Required actual lifecycle hooks (root-owned sources)

1. In actual native headless-policy setup after main-role admission, call `ConfigureDiagnostics(Sys_CmdlineIntValue(commandLine,"bo1_frameperf"), Sys_CmdlineIntValue(commandLine,"bo1_hitchwatch"), Sys_CmdlineIntValue(commandLine,"bo1_threaddump"))`. This uses the canonical last whole-word parser. Negative thresholds fail explicitly. Frameperf also applies outside headless; hitch/thread dump are headless only; thread dump suppresses hitch as originally.
2. Include the new header in canonical native Sys_Init and call `RegisterDiagnosticsDvars()` before startup commands/config execute. The original Windows autoquit/quitnotify/dvardump registrations are already under `!__ANDROID__`; new native registration supplies original defaults/domains without duplicates.
3. Immediately after actual Com_Init returns in native main, call `DiagnosticsInitializationReturned()` alongside the existing genuine shutdown phase publication. This creates the real monotonic origin and starts an observer only when requested. Notify events can be counted during init, but no timeline/quit action runs before this hook.
4. After each actual Com_Frame, call `DiagnosticsFrame()`. It reads actual server-running Dvar, client connection state when present, HUD observations and level.time. It logs timeline changes and calls actual Com_Quit_f on mature original notify/real-time autoquit deadlines; autoquit optionally enumerates actual Dvars.
5. In actual Com_Quit_f after its initialization-entry guard and BEFORE recorder/thread synchronization, server park, error lock or logger/allocator teardown, call `StopDiagnostics()`. It requests exit and joins only this owned observer. This also safely handles the offdefault case. Partial pre-init fatal exits remain dirty terminal exits, not a false clean diagnostics/full-engine cleanup.

The watcher preserves 10ms sampling, four dumps per watched frame, 200ms spacing and 240 total hitch evidence limit. Frame sequence/start publication uses native atomics. Separate requested thread dumps run at requested delay and another 10 seconds. Evidence is emitted directly to stderr and consists of actual `/proc/self/task/*/stat` and `wchan` reads, with explicit errors on unavailable files. It explicitly declares remote userspace stacks unavailable; it never suspends workers, labels arbitrary words as frames, or claims Windows DbgHelp equivalence. Output is stderr, not the Windows `main/bo1_threads.log` file.

HUD and notify observations use a private mutex. Engine logging, fatal reporters and quit callbacks occur after releasing it. Configuration/registration/init publication require the actual process/main role; configuration is one-shot, and observer retirement is terminal. Frame timing and level deadline addition use widened arithmetic. Original valid notify grammar and process-wide counts are retained; scripts/restarts are not fabricated. Rendered client screenshot/menu-command automation is outside this batch.
