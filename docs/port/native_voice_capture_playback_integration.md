# Native canonical voice capture and playback

This batch restores the original Voice/groupvoice owners with the matching bundled Speex codec. It does not establish rendered Android microphone or physical playback readiness. Original headless Voice_Init registers its four dvars, returns before codec/device creation, and leaves g_voice_initialized false.

## Implementation and contracts

Selected originals are src/win32/win_voice.cpp and src/groupvoice/{encode,decode,record,play,record_dsound,play_dsound}.cpp. Native platform ownership is src/platform/android/voice_audio.h/.cpp. Native branches retain the canonical mono PCM16 8192 Hz capture/playback contract, Speex NB 8000 Hz nominal protocol with 160-sample frames, quality/VAD/DTX options, 32 talkers, 33 reusable sample slots, and original jitter thresholds (320/6000/10000 bytes, 6000-byte start). Integer frequency changes and original hysteresis remain. The Windows DirectSound/mixer branches remain selected on normal Windows builds.

Capture opens the actually enumerated SDL capture route (or actual unnamed default), requesting standard 48000 Hz mono PCM16. A real SDL_AudioStream converts callback PCM to canonical 8192 Hz. It retains SDL resampler state between callbacks; no invented output frames or silent replacement are appended. AudioStream errors latch actual failure. SDK callback PCM crosses a mutex-protected 25600-frame ring; overflow drops the oldest captured frames and counts loss. Application microphone gain saturates PCM16 and mute clears pending capture/converter storage on transition. Route metadata reports the actual selected named route and fails if unnamed or insufficient capacity. Windows global mixer/routing writes are unsupported on native; application controls do not claim to alter global Android mixer state.

Opening capture requires the actual synchronized SDL event owner, actual existing SDL audio subsystem, completed real SDL Java setup and the actual Activity's granted RECORD_AUDIO permission. These are checked before device access. No neutral-success result is returned for an uninitialized provider. Permission requests belong to the real Activity lifecycle; this provider only checks an existing grant.

Playback uses the existing real FAudio game engine/masterBus rather than opening another SDL output device (Android SDL supports one output device). Each talker owns an actual FAudio source voice, with copied PCM storage retained through actual completion callbacks. Pending codec packets are aggregated into SDK buffers to retain the canonical 51200-byte backlog contract without exhausting FAudio's 64-buffer queue. Accepted byte counts express real partial backpressure. Actual SamplesPlayed determines backlog and jitter, and active destruction quiesces callbacks before storage retirement. Existing game sound driver/FAudio bridge files were not modified by this batch.

Native-specific source safety repairs use actual codec frame bounds, Speex control return codes, checked quality updates, exact partial-frame assembly, saturation instead of wrapping, and reusable validated sample slots. Decode writes exactly 160 shorts and returns 320 bytes; it does not reproduce the original erroneous byte-count-as-short-count write. The original Windows branch remains intact. Native sample layout is explicitly checked at 80 bytes on the supported 64-bit targets.

## Production integration recipe

Add android/cmake/native-speex as a subdirectory. Link bo1_native_speex PUBLIC to selected state/database producers and to the final executable so its generated speex/speex_config_types.h include directory propagates. This target builds the actual bundled Speex 1.1.9 C sources from its existing Makefile inventory, uses the bundled type template and actual misc.c allocation routines, and links m on native. Do not separately select obsolete Windows win_libspeex_misc.cpp allocation definitions. No new external codec is introduced.

Select the seven original C++ files listed above plus platform/android/voice_audio.cpp; existing FAudio/controller/window owner sources and libraries are required. Retire corresponding unavailable Voice_* diagnostics only when these actual owners are selected. BO1_NATIVE_FAUDIO_HOST_TEST is fixture-only and must not be a production definition.

Voice_HasOwnedResources reports actual encoder/decoder pointers or capture/sample ownership, independently of g_voice_initialized. Voice_Shutdown retires genuine partial initialization and is idempotent. Call it on the actual SDL control owner before SND_Shutdown and before event/window retirement. Close capture first where partial device failure prevents Stop; SDL_CloseAudioDevice quiesces callbacks. The real Java/window lifecycle must retire setup ownership before Activity refs disappear, and reinitialize it only through the existing actual setup operation. Teardown/recreation has not been certified by these tests.
