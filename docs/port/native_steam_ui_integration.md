SDL Java setup is a genuine precondition: actual SDLJavaSetupComplete acquire publication is checked before SDL_AndroidGetJNIEnv or SDL_AndroidGetActivity, whose underlying JNI key is unsafe before actual setup. Service validates JNI environment, pending exception absence, local-frame allocation, real Android Activity instance, JavaVM, loader and helper methods. Attached native workers resolve app helper with the actual Activity.getClassLoader/loadClass, not app FindClass assumptions. Bootstrap Android/Java classes use the boot loader. UTF-8 bytes are converted via actual Java String(byte[],UTF-8), avoiding modified-UTF-8 mismatch for localized text. JNI-owned exceptions are described then cleared; local refs retire before native engine logging. Caller-supplied existing pending exception is rejected without discarding it.

Headless preserves no dialog/no external launch policy, returning false or logging explicit refusal. URI must be steam://; Java validates Steam scheme, uses real Intent.ACTION_VIEW and actual Activity.startActivity on UI thread, catches IntentNotFound/Security/Runtime failures. Success means Android accepted startActivity, not Steam/backend readiness. Worker waits for actual UI action outcome. A thirty-second queued-dispatch deadline cancels a request that has not launched; a dispatch mutex prevents timeout cancellation racing into a late launch. If launch is already executing, worker observes its actual returned outcome instead of declaring false before an already executing side effect. UI caller launches synchronously and never waits on itself.

Steam error helper rejects a caller on the actual Android main/UI looper. Worker posts a real AlertDialog; it waits for actual show, then actual user dismissal. Since the canonical caller immediately quits, it cannot report a synthetic completed dialog while the user has not dismissed it. Activity destruction releases the worker with failure; listener registration and dialog cleanup retire on UI. Queued-show timeout and worker interruption cancel explicitly. A stopped UI dispatcher or invalid Activity yields failure/log. Dismissal wait deliberately has no arbitrary user timeout; UI remains free to render/respond. This owner does not configure SDL, publish JNI readiness or modify the current development bootstrap.
