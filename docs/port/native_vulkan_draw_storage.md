# Fence-retired native draw storage

2026-10-15 stage73. Actual SDK592/stage161 failed the fixed2MiB material uniform arena during the real BSP depth prepass. The old uploader allocated/wrote two4096-byte float banks on every draw, whether reflected or unused, limiting this arena to at most256 such uploads. Existing GPU readers cannot be repaired by overwriting the same ranges or replacing their backing buffer.

DrawStorage now owns reusable1MiB coherent host-visible uniform pages and matching descriptor pools, allocated on demand. Each page admits up to128 draw packets/two stage sets; the frame slot has an explicit64-page bound. A full page advances to another real buffer/pool without moving existing GPU ranges. The owner rejects reset of recorded readers and polls the actual successfully submitted VkFence before reusing any range or descriptor pool. Pages persist for reuse; the renderer's existing BeginWork waits the selected slot fence, and the successful submission callback records its actual fence. EngineFrames drains device work before destruction. Window triangle storage is separate4096-byte memory; frame material pages no longer compete with it.

The paged material upload path validates reflected resource banks/textures first and writes only used float constant banks, with physical-device alignment. Integer/boolean banks remain explicit unsupported. Original immutable draw/texture/geometry/program packets remain retained through the frame fence. The old explicit-buffer overload remains for historical standalone preview fixtures; the full engine passes its actual DrawStorage through pass/material recording. Page budget, allocation errors and illegal resets fail explicitly. No draw is discarded or bounds check removed.

Actual Adreno610 Vulkan1.1.128 focused test uses four buffers/four descriptor pools and real SM3 shader draws, with8 float-RGBA GPU pixels across two submissions. A host-controlled Vulkan event holds the real queue pending to verify reset rejection deterministically; after the event opens, actual fences/readback pass. The second submission reuses the same buffer/pool handles after retirement while all colours remain independent. Recorded reset, before-reset allocation, oversized/zero-alignment allocations, bounded page overflow and cleared failure output checks pass. A zero-constant allocation is admitted. This verifies storage and descriptor/range lifetime; it is not complete-game or performance proof. Historical shader/depth/copy families were skipped.
