New OcclusionQueries owns a real bounded VkQueryPool, reset/begin/end recording, per-query result caching and generations. Reset records outside render passes; active/repeated begin/end and reset of an unpublished recording fail explicitly. Submitted accepts the actual reset-before-submit frame fence ONLY through a successful queue-submission callback. Read is pending before publication or fence completion, then reads64-bit result plus availability without WAIT/flush. Vulkan errors remain failures. Destruction/reset requires caller-retired GPU users; legacy query owner adaptation and generation reuse/failure runtime tests remain pending.

Presentation now enables precisely the available occlusionQueryPrecise optional feature, exposes its enabled value, and calls SubmittedFrame only after actual vkQueueSubmit success. Other optional features stay disabled. Exact sample counts use VK_QUERY_CONTROL_PRECISE_BIT; without it, only zero/nonzero visibility is promised. Reference: https://docs.vulkan.org/spec/latest/chapters/queries.html . Diagnostic query callback ties the pool to the correct submission/slot and reads after slot retirement.
