## Investigation history

User-supplied Opus review is useful for the next phase: separate optimized performance configuration, immutable shader identity keys, sampler reuse, vertex capability caching, buffer suballocation, and depth-free postprocessing. These are candidates, not implemented improvements. The current native scene framebuffer is BGRA8, explicitly checked in its initializer, rather than the float format suggested in the review. Debug slowdown factors and FP16 throughput gains require measurement; RelaxedPrecision does not guarantee16-bit execution. Removing a depth copy requires proving unchanged depth between consumers; whole-atlas clear requires proving no retained regions are needed. Canonical diagnostics remain enabled. Detailed GPU pass sampling is every tenth frame, but CPU draw-phase timers and whole-scene GPU timing still run each frame.

## Stage89: genuine sampled hardware depth

The native adapter deliberately set supportsIntZ=false because native depth copies were missing. Consequently the engine renders an additional full-resolution geometry pass to R32F before its ordinary depth prepass. A real D24S8 depth-copy provider now implements the hardware-depth route: separate sampled destination with comparison disabled, actual matching image/extent validation, ended source pass, depth and stencil copy regions, source/destination barriers and journal updates only through real submitted work. Both owners remain in the fence-retired pass arena. The existing hardware-depth material/DOF variants consume the actual copied depth. This does not fabricate vendor API support; no D3D vendor call runs in the native branch. Missile-camera R32F fallback remains.
