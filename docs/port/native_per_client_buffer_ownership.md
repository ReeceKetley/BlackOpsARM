# Native per-client buffer ownership

2026-10-13. Actual full411 console map zombie_theater reaches AllocatePerLocalClientMemory after a clean production initialization/frame/quit baseline. The map run rejects borrowed hunk tracking; the corresponding tracker implementation is a separate coordinated change. This report covers the primary client allocation and lifetime repair, whose production execution is pending the next full build.

On Android, client and connection blocks use their actual sizeof and alignof. sizeof(clientActive_t) already includes the expanded parse-entity ring; adding CL_PARSE_ENTITIES_EXTRA_BYTES again inflated this allocation. Windows retains the validated reference formula. The native capacity sums actual primary blocks, their maximum alignment padding, offsetof(HunkUserDefault,buf)+31 for the real hunk cursor, and the companion providers' native budgets. Counts are bounded to actual engine domains and total size must fit the existing integer hunk API; no arbitrary arena increase is introduced.

Native CL_FreePerLocalClientMemory now releases all FX/CG/SV hunk consumers and destroys the borrowed hunk/tracking owner before PMem_Free releases its underlying buffer. The original ordering freed PMem before those consumers could dispatch Hunk_UserFree through its header. Windows keeps its original ordering. Real client/header pointers are nulled after retirement; the borrower never owns an independent OS mapping.
