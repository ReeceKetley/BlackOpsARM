# SM3 repeat control flow and native resource startup, stage46

Compiler lowers REP/ENDREP to GPU counter loops before I/O/flat-constant normalization and control-flow flattening. Each repeat copies integer registerX into a unique signed temporary, enters a structured loop, breaks when count<=0, runs the original body, decrements and continues. It does not mutate the source integer register or unroll only a specific asset. Nesting has independent counters. Existing flattening emits actual Vulkan-compatible branch/LoopMerge structure. Synthetic LOOP0-source validation is accepted while parsed legacy LOOP2-source remains separately checked.

The shader scanner now distinguishes REP blocks and matching ENDREP and treats them as breakable loop scopes, preserving mismatched-block rejection. BREAK_comp is lowered through the existing comparison/predicate machinery to BREAKP. Native legacy LOOP/aL iteration semantics remain explicitly unsupported rather than being silently treated as an endless generic loop; it is a separate pending family.

Primary semantics: https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/rep---ps specifies integerX count[0,255], unchanged source register and nesting; https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/break-comp---ps specifies nearest-loop conditional exit. Negative-count test is additional robustness outside the documented legal count domain, not D3D9 parity evidence for invalid input.
