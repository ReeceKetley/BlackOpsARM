# Native collision viewer integration

Frozen canonical sources: `src/qcommon/cm_showcollision.cpp/.h`. Select the real cpp in the production target; no new defines, replacement services, associated global layouts or brush_edges source edits are needed. Source hashes are in `build-android-audit/native_collision_viewer/frozen-sources-sha256.json`. Root owns CMake, unavailable endpoints, ledger and normal Windows/production comparisons.

Native repairs retain original intersection, snapping, point deduplication, projected hull, representative triangle and reversal algorithms. ShowSingle now owns the required 1024 ShowCollisionBrushPt entries and six axial rows. Axial construction/access and face point lists use actual typed subarrays rather than indexing past a four/three-element first row. Axial plane indices are distinguished from nonaxial side indices before accessing sides[index-6]. Projection chooses axes using floating absolute normals rather than converting negatives to unsigned.

The local header adds a native runtime-only CMShowCollisionWinding with actual 1024x3 owned float rows. All viewer helper callers are inside this canonical cpp; the Windows alias is original winding_t and Windows accessor macros retain original p accesses. Global common/brush_edges.h winding_t remains its original p[4], sizeof52, and no serialized layout/packing/assertion is changed. Native helpers check counts, physical tail indices, growth, axes, input ownership and side-index limits. Brush validation rejects missing side/plane ownership, nonfinite or unordered bounds and unrepresentable signed16 side indices. Existing Com_Error limit sites abort on native if the fatal/drop reporter unexpectedly returns, before a following write.

The actual box fixture uncovered one further defect: CM_RepresentativeTriangleFromWinding compares fabs(dot), then assigns -dot. It rejected three of six real box faces (failed HONOR runs1/2 preserved). The native assignment now stores fabs(dot), matching the already-canonical common/brush_edges.cpp RepresentativeTriangleFromWinding magnitude behavior. Original PlaneFromPoints and ReverseWinding still choose orientation. The original Windows signed assignment remains unchanged.

Viewer temporary storage is automatic and owned per invocation (~33 KiB for intersection+winding scratch, plus the existing roughly12 KiB face builder scratch), so reentrant callbacks do not share global windingPool. No allocator or fake temporary owner is introduced. Canonical LargeLocal only permits main/server while this viewer has a genuine render backend caller (rb_showcollision.cpp); using it would incorrectly reject rendered calls. Global CM_Hunk temporary-high reset would interfere with other owners. The fixture verifies this real automatic-storage lifetime with canaries and a nested viewer callback; it does not claim a new engine allocator path.

Validation: `tools/port/tests/build-native-collision-viewer.ps1` compiles the whole canonical TU for aarch64 Android API28 with UBSan and links `native_collision_viewer_tests.cpp` with actual cm_showcollision.cpp, com_math.cpp, assertion_services, stack_trace and fatal_error. CPU polygon collector inspects emitted vertices and recursive storage; it does not draw or claim GPU readiness. Com_Error is an isolated deliberately returning reporter so limit guards prove abort-before-write behavior; the real native assertion/fatal owners are linked.
