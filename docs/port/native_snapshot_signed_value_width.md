Protocol audit establishes that canonical plain negative NetFields are only -8/-16: MatchState alliesScore/axisScore/scoreLimit use size4/-16; loopSoundFade/throttle use size2/-16; movement/viewheight/cursor examples use size4/-8. Actual `MSG_GetField` reads signed char/short/int with native signed-char compilation. The paired reader decodes abs(width), XORs the masked baseline, and sign-extends only when the original width was negative and its decoded sign bit is set. Magnitude masking therefore preserves the actual -8/-16 wire bytes. Legacy x86's undefined negative shift may mask the count differently for hypothetical -24/-31 and lose higher field bits; this report does not claim generic identity with that undefined runtime behavior. The defined native magnitude-width contract for ±31/±32 is verified against independent wire expectations and the paired actual reader. Windows behavior remains unchanged through its original source branches.
