# Native compressed image upload — stage 8

2026-10-14. Goal incomplete. SDK492/stage61 BuildId57599833235cab67855cd9bd3e9dd8ffde5459db installed and tested. Changes after pre-native checkpoint remain uncommitted.

DXT1/3/5 canonical image creation now allocates an RGBA8 sampled Vulkan image. QueueUpload decodes BC1/2/3 source blocks once into its immutable upload snapshot, then the existing renderer staging/subresource path uploads decoded texels. No per-frame decoding or asset mutation. Block decoder reads little-endian bytes without aligned casts, clips partial XY blocks and handles successive volume slices. It validates exact block byte counts, dimensions and multiplication overflow. Canonical pointer-only upload API still relies on its producer supplying a valid source range; full FastFile resource-range execution remains pending.

Current device creation enables no optional BC compression feature. Therefore this is a portable decoded fallback, not a hardware BC path. RGBA8 expands BC1 data by up to8x and BC2/3 by up to4x; CPU snapshots also consume memory. Optional hardware BC capability/feature negotiation, streaming budgets and retirement of CPU upload snapshots remain required optimization work before assessing whole-game memory/performance. CPU decoding currently holds the image publication mutex; parallel streaming contention is not measured.

ARM64 decoder executable passed on the authorized tablet: BC1 transparent index/endpoints, BC2 explicit alpha and forced four-color mode with increasing endpoints, BC3 both endpoint ordering modes/all eight alpha selectors, unaligned input,1x1x2 edge-volume mip and truncated/invalid input.
