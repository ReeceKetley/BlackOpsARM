## Contract and implementation

The Windows oracle uses the bundled Bink 1.9i SDK (2008-10-31), two decoded frame-buffer sets, Y/Cr/Cb/optional A textures, resource callbacks, jobqueue dispatch, critical sections, pause/skip/wait/loop flags, disk IO controls and SND cinematic notifications. Normal Windows keeps its original SDK/DirectSound branches. Native bink_service.h is an explicit engine-consumed API surface, not binary compatibility with the proprietary DLL. Public headers forward-declare audio owners; FAudio/FFmpeg headers stay private.

Read-only census of all 50 main/video files: every marker is BIKi; 49 are 1280x720 and one is 1024x1024, with several rational frame rates. All video flags are zero, so no alpha input exists in this census. All 88 audio tracks are 48 kHz Bink DCT: 64 stereo, 24 mono. Observed IDs are subsets of 0..3; original selected IDs 0..4 and volume assignment (0/1 gain, 2..4 muted) remain. Largest compressed input: 100415896 bytes; total census bytes: 1299038476. This is metadata evidence, not decoding all movies.

Open validates marker, exact declared size, dimensions/frame count and the canonical 32-bit millisecond duration before publishing a handle. Real custom memory AVIO performs bounded reads/seeks; actual decoder contexts produce pitched Y/Cr/Cb/optional A planes. Invalid registration geometry, buffers/pitch, codec output, malformed input, allocation failure and unsupported formats fail explicitly. No silent/generated/padded frames replace actual output.

The original scheduling, texture/resource path, image/hunk ownership and default-file retry remain. Native clearing uses sizeof instead of x86 constants; texture upload checks actual LockRect/pitch/UnlockRect. Fractional SP playback volume survives the native internal boundary. Rational timing uses overflow-safe rescaling. Native Core and public queries serialize actual Movie lifetime with the existing recursive cinematic critical section; pause target reads use the target-change lock. Existing interlocked worker publication remains. No thread/window/game sound-driver implementation was replaced.

## Genuine bounded preload policy

Native explicitly reads the complete validated physical file into owned CPU storage before Open succeeds. Paths remain rooted in canonical Sys_Cwd main/video and raw/video resolution with native separators. Real file open/read/close matches the original SDK's physical-file ownership; it does not claim an engine VFS handle. Resident rawfile opening receives actual len and copies the validated span, never inferring safe memory extent from a raw pointer/header alone.

r_cinematicNativeInputBudgetMiB defaults to 256 and accepts 1..1024. Allocation is bounded before read/copy; default covers the observed retail maximum. This bounds compressed input, not total memory: canonical 24 MiB hunk, frame planes, GPU textures, decoder state and audio buffers add storage, and a DB rawfile coexists with its owned copy. Native stats report the actual retained complete input. Canonical IO controls have no outstanding file read to suspend after Open completes. No invented asynchronous reader or fabricated percentage is used. This differs from Windows asynchronous cache policy and trades memory/open latency for bounded ownership.
