# Native explicit frame transactions, stage40

Presentation now exposes BeginFrame, BeginWindowPass, EndWindowPass and SubmitFrame. The callback Render convenience API delegates to the same operations. Android diagnostic entry uses the explicit API directly and checks material errors before submission.

BeginFrame waits the actual frame-slot fence, acquires a real swapchain image and starts command/image recording. The image journal stays alive across engine calls and commits only after successful vkQueueSubmit. Submit publishes actual query/event fences and presents using the per-image semaphore. Steady frames retain two fence-retired slots without queue/device idle.

The SDL/queue owner is enforced. Duplicate starts, nested/repeated window passes, inactive pass ends and submission without an ended window pass reject without publishing work. Submission callbacks cannot reenter presentation. Errors after acquisition during command reset/begin/end/fence-reset/queue-submit poison the presenter for teardown, preventing unsafe reuse of an unconsumed acquire semaphore. Lifecycle deferred/out-of-date paths remain; SUBOPTIMAL still usable. This transaction currently requires a window pass, so offscreen-only/partial startup submissions remain pending.
